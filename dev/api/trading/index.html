Trading

An order model says what to trade, and the verb says what to do with the order. submit opens each leg, close reverses each leg, and roll closes the old legs and opens the new legs. An option leg has no position intent, so the same vector of MyOptionLegModel values can be passed to submit, close, and roll.

close adds methods to Base.close for an AlpacaClient, so using Alpaca does not clash with Base.close.

Covered calls and other mixed orders

Alpaca cannot fill shares and options in one order, so submit and close send a MyMixedOrderModel as two orders in a fixed sequence. The sequence keeps a short call covered at every step.

  • submit sends the equity order and polls the equity order until it fills. It then sends the option order.
  • close sends the reverse option order and polls the option order until it fills. It then sends the reverse equity order.
  • The keyword fill_timeout is the number of seconds to wait for the first order. If the first order does not fill in time, or polling the first order fails, the method cancels the first order and reads the first order again. When the first order filled before the cancel took effect, the sequence continues. Otherwise the method sends nothing else and throws an AlpacaSequenceError that holds the first order.
  • The method does not wait on the second order. The returned vector holds the filled first order and the second order as Alpaca accepted it.
  • If Alpaca rejects the second order, the method throws an AlpacaSequenceError that holds the filled first order. The account then holds the shares without the short call, or the shares without the call that was bought back.

Before submit sends anything, the method checks that the shares cover every short call in the model. When any option leg sells a call, the equity side must be "buy", the equity model must set qty and not notional, and the share quantity must be at least 100 * qty times the sum of the ratio values of the short call legs. A model that fails the check raises an ArgumentError, and the method sends no request. close sells all the shares of the model, so close raises an ArgumentError before any request when the shares cover more than qty units of the short calls. Pass close the same qty as the submit call.

Orders from an earlier session

The reads return a DataFrame, so an Order comes only from submit, close, or roll. Across sessions, pass the legs to close and roll, and pass the order id from the id column of an orders DataFrame to cancel.

Submit one equity or ETF order, using an HTTP POST call to the Alpaca /orders endpoint.

Arguments

Alpaca.submit — Method
submit(client::AlpacaClient, m::MyMixedOrderModel; qty = 1, type = "limit", limit_price = nothing, time_in_force = "day",
    fill_timeout = 30.0, poll_interval = 0.5) -> Vector{Order}

Submit shares and options together as two orders, because Alpaca cannot fill them in one order. The method first sends the equity order at market and waits until it fills. It then sends the option order, which is one single-leg order or one multi-leg order. The method does not wait on the option order.

Arguments

  • client::AlpacaClient: the client that holds the credentials and the base URLs.
  • m::MyMixedOrderModel: the structure that holds the equity part and the option legs.
  • qty::Int: the number of units of the option legs. The share quantity is the qty of the equity model.
  • type::String: the type of the option order, "market" or "limit".
  • limit_price: the limit price of the option order, or nothing.
  • time_in_force::String: the time in force of the option order, e.g., "day".
  • fill_timeout::Real: the number of seconds to wait for the equity order to fill.
  • poll_interval::Real: the number of seconds between two polls of the equity order.

Returns

  • Vector{Order}: the filled equity order and the option order as Alpaca accepted it. The method does not wait for the option order to fill.

Throws

  • ArgumentError: when the shares do not cover a short call, when qty < 1, when poll_interval is not a finite number greater than 0, when fill_timeout is not a finite number of 0 or more, or when either order is invalid. The call sends no request.
  • AlpacaError: when Alpaca rejects the equity order. The method sends no option order.
  • AlpacaSequenceError: when the equity order does not fill, or when the option order fails. The error holds the equity order. When the equity order does not fill in time, or polling the equity order fails, the method cancels the equity order and reads the equity order again. An equity order that filled before the cancel took effect continues the sequence. Any other equity order stops the sequence before the option order, and cause holds the polling error when polling failed. When the option order fails, e.g., Alpaca rejects it, cause holds that error.

Base.close — Method
Base.close(client::AlpacaClient, order::Order; type = "market", limit_price = nothing, time_in_force = "day") -> Order

Close a filled order by submitting the reverse order, using an HTTP POST call to the Alpaca /orders endpoint. The method first reads the current state of the order from Alpaca, using an HTTP GET call to the /orders/{id} endpoint, so the Order that submit returned works once that order has filled. The reverse order uses the filled quantities of the order as read. The kind of the order comes from the order as read: an order with legs is a multi-leg order, an order with the asset class "us_option" is a single option order, and any other order is an equity order.

Arguments

  • client::AlpacaClient: the client that holds the credentials and the base URLs.
  • order::Order: the order to reverse, e.g., the Order that submit returned. The method uses the id of order to read the order again.
  • type::String: the type of the reverse order. Use "market" or "limit".
  • limit_price: the limit price of the reverse order, or nothing. For a multi-leg order, this is the net price of one unit of the structure.
  • time_in_force::String: the time in force of the reverse order, e.g., "day".

Returns

  • Order: the reverse order as Alpaca accepted it.

Throws

  • ArgumentError: when the status of the order as read is not "filled". Use cancel for an order that has not filled, and close(client, symbol; qty) for the filled part of a canceled or expired order. The call sends no order.
  • AlpacaError: when the read of the order fails, or when Alpaca rejects the reverse order. When the read fails, the call sends no order.

Base.close — Method
Base.close(client::AlpacaClient, m::MyMixedOrderModel; qty = 1, type = "limit", limit_price = nothing, time_in_force = "day",
    fill_timeout = 30.0, poll_interval = 0.5) -> Vector{Order}

Close shares and options together as two orders. The method first sends the reverse option order and waits until it fills. It then sends the reverse equity order at market. The method does not wait on the equity order.

Arguments

  • client::AlpacaClient: the client that holds the credentials and the base URLs.
  • m::MyMixedOrderModel: the structure to reverse.
  • qty::Int: the number of units of the option legs. The share quantity is the qty of the equity model. Pass the same qty as the submit call. The method buys back qty units of the option legs and then sells all m.equity.qty shares. Let s be the summed ratio of the short call legs. When s > 0 and m.equity.qty >= 100 * (qty + 1) * s, the shares cover more than qty units of the short calls, and the method throws an ArgumentError, because selling all the shares would leave a short call uncovered.
  • type::String: the type of the reverse option order, "market" or "limit".
  • limit_price: the limit price of the reverse option order, or nothing.
  • time_in_force::String: the time in force of the reverse option order, e.g., "day".
  • fill_timeout::Real: the number of seconds to wait for the option order to fill.
  • poll_interval::Real: the number of seconds between two polls of the option order.

Returns

  • Vector{Order}: the filled option order and the equity order as Alpaca accepted it. The method does not wait for the equity order to fill.

Throws

  • ArgumentError: when the shares cover more than qty units of the short calls, when qty < 1, when poll_interval is not a finite number greater than 0, when fill_timeout is not a finite number of 0 or more, or when either reverse order is invalid. The call sends no request. A model that holds more shares than its short calls need is closed by closing the option legs and the shares separately.
  • AlpacaError: when Alpaca rejects the reverse option order. The method sends no equity order.
  • AlpacaSequenceError: when the option order does not fill, or when the equity order fails. The error holds the option order. When the option order does not fill in time, or polling the option order fails, the method cancels the option order and reads the option order again. An option order that filled before the cancel took effect continues the sequence. Any other option order stops the sequence before the equity order, and cause holds the polling error when polling failed. When the equity order fails, e.g., Alpaca rejects it, cause holds that error.

Alpaca.roll — Function
roll(client::AlpacaClient, from, to; qty = 1, type = "limit", time_in_force = "day",
    limit_price = nothing, client_order_id = nothing) -> Order

Roll option legs from one set of contracts to another, using an HTTP POST call to the Alpaca /orders endpoint. The call sends one atomic mleg order. Each from leg is reversed with the position intent buy_to_close or sell_to_close, and each to leg is opened with the position intent buy_to_open or sell_to_open. limit_price is the net price of one unit of the structure (positive is a debit, negative is a credit).

roll covers a single contract (2 legs) and a vertical spread (4 legs). An iron condor has 8 legs, so it rolls as two roll calls, one for each wing. The two calls are not atomic: the first order can fill while the second order does not.

Arguments

  • client::AlpacaClient: the client that holds the credentials and the base URLs.
  • from::Union{MyOptionLegModel,Vector{MyOptionLegModel}}: the legs to close.
  • to::Union{MyOptionLegModel,Vector{MyOptionLegModel}}: the legs to open.
  • qty::Int: the number of units of the structure.
  • type::String: "market" or "limit".
  • time_in_force::String: the time in force of the order, e.g., "day".
  • limit_price: the limit price, or nothing. A limit order requires it.
  • client_order_id: the order identifier assigned by the client, or nothing.

Returns

  • Order: the order as Alpaca accepted it.

Throws

  • ArgumentError: when qty < 1, when the from and to legs together are fewer than 2 or more than 4, when a leg is invalid, or when a "limit" order has no limit_price. The call sends no request.
  • AlpacaError: when Alpaca rejects the request.

roll(client::AlpacaClient, from::Order, to; qty = nothing, type = "limit", time_in_force = "day",
    limit_price = nothing, client_order_id = nothing) -> Order

Roll the legs of a filled option order to another set of contracts. The method first reads the current state of from from Alpaca, using an HTTP GET call to the /orders/{id} endpoint, so the Order that submit returned works once that order has filled. The legs of the order as read are the legs to close. A single option order is one leg, and a multi-leg order is one leg for each of its legs. When qty is nothing, the call uses the filled quantity of the order as read. The call sends one atomic mleg order, as described for roll(client, from, to). An iron condor rolls as two roll calls, one for each wing, and the two calls are not atomic.

Arguments

  • client::AlpacaClient: the client that holds the credentials and the base URLs.
  • from::Order: the option order that holds the legs to close, e.g., the Order that submit returned. The method uses the id of from to read the order again.
  • to::Union{MyOptionLegModel,Vector{MyOptionLegModel}}: the legs to open.
  • qty: the number of units of the structure, or nothing to use the filled quantity of the order as read.
  • type::String: "market" or "limit".
  • time_in_force::String: the time in force of the order, e.g., "day".
  • limit_price: the limit price, or nothing. A limit order requires it.
  • client_order_id: the order identifier assigned by the client, or nothing.

Returns

  • Order: the order as Alpaca accepted it.

Throws

  • ArgumentError: when the status of the order as read is not "filled", when the order is an equity order (use close or submit for shares), when qty < 1, when the legs together are fewer than 2 or more than 4, or when a "limit" order has no limit_price. The call sends no order.
  • AlpacaError: when the read of from fails, or when Alpaca rejects the roll order. When the read fails, the call sends no order.
