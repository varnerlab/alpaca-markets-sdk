Reading data

Reading has two steps. url builds the request URL from a read model, and api sends the request, follows next_page_token until the last page, and returns the result of the handler.

using Alpaca
using Dates

client = load_client()

model = MyStockBarsEndpointModel(symbols = ["AAPL", "MSFT"], timeframe = "1Day",
                                 start = Date(2025, 1, 1), finish = Date(2025, 6, 30))
url(client, model)           # the URL of the first page
bars = api(client, model)    # a DataFrame with every page

The default result

The default handler of every read model returns a DataFrame. An endpoint that returns one record, such as the account, the clock, one asset, one order, one position, or one contract, returns a DataFrame with one row.

A missing value is missing in a column. Timestamps are DateTime in UTC, and prices and sizes are Float64. The tables of account activities, account configurations, corporate actions, and fixed income keep the values as Alpaca sends them, so some prices and sizes in those tables are text. The columns of a bars table are timestamp, symbol, open, high, low, close, volume, trade_count, and vwap. A snapshots table has one row for each contract, and the nested objects (the latest quote, the latest trade, and the greeks) are columns with a prefix.

MyAssetsEndpointModel has no tradable_only field, because tradable_only is not an Alpaca query parameter. To keep only the tradable assets, filter the tradable column of the DataFrame.

MyLogoEndpointModel is the one read model whose default handler does not return a DataFrame. It returns the PNG image as a Vector{UInt8}.

Writes through api

The write models, such as MyCreateWatchlistEndpointModel, MyUpdateAccountConfigurationsEndpointModel, and MyReplaceOrderEndpointModel, also go through api. api sends the HTTP method of the model, sends each write once, and never follows next_page_token for a write. A write that Alpaca answers with no body, such as MyExerciseOptionEndpointModel or MyDeleteWatchlistEndpointModel, returns an empty DataFrame.

Custom handlers

The handler keyword of api replaces the default handler. A handler is a function of the model type and the response body as a String: handler(Type, body). A handler sees only the response, so any step that needs a value from the request happens after api returns.

Alpaca.api — Function
api(client::AlpacaClient, model::AbstractAlpacaEndpointModel;
    handler::Function = _default_handler, max_pages::Union{Nothing,Int} = nothing)

Make the HTTP call for an endpoint model and process the response body with a handler. A paginated endpoint is called once for each page, and the handler results are merged in page order. A model whose HTTP method is not GET sends one request, with the JSON body of the model, and is never paginated.

Arguments

  • client::AlpacaClient: the client that holds the credentials and the base URLs.
  • model::AbstractAlpacaEndpointModel: the endpoint model that describes the request.
  • handler::Function: the function that receives the type of the model and the body of a page as a String.
  • max_pages::Union{Nothing,Int}: the number of pages after which a paginated request stops. nothing follows every page. A write model sends one request and never follows pages, but max_pages = 0 throws before a write too.

Returns

  • The result of the handler. A paginated endpoint returns the merged result of all pages.
  • A DataFrame result that max_pages stopped carries the next page token in its metadata under "next_page_token", which you read with metadata(df, "next_page_token", nothing).

Throws

  • AlpacaError: when the response status is not in the range 200 to 299.
  • ArgumentError: when max_pages is less than 1. The call sends no request.
